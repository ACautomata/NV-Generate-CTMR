DCU / TorchInductor / Triton · 工程故障报告

Compile 路径故障

在匹配的 DTK 26.04、torch-dcu 2.9 与 Triton 3.5.1 DCU 构建上，大体积 Conv3d 的反向传播触发 Triton 4-warp shared-memory lowering 失败并导致进程段错误。

复现状态：稳定失败 严重性：阻塞 torch.compile 训练 数据内容：未涉及 目标：gfx936

01 / 结论

不是装错 Triton，而是正确 DCU 构建中的一个特定 codegen 分支失效。

高置信度诊断

图捕获、基础 Triton kernel、3D 卷积前向和小尺寸 3D 训练图都可运行。失败只在默认 nnU-Net patch 尺寸下、Conv3d.backward() 所触发的 shared-memory 4-warp Triton reduction 中出现。故障停在 Triton 的 LLVM IR → AMDGCN 后端阶段，尚未形成目标 HSACO code object。

本报告不声称已经定位到供应方内部库的单一源文件；它记录的是可重复的边界、生成 IR 与可用于修复的具体失败候选。

03 / 最小复现

只需一个 Conv3d，即可离开 nnU-Net 复现

以下探针只使用随机张量，不读取训练数据。原始 nnU-Net 训练默认 torch.compile 同样失败；最小测试的 fullgraph=True 仅用于将诊断图固定为单一编译单元。

最小 Python 探针DCU / GPU 0
import torch
from torch import nn

model = nn.Conv3d(4, 8, kernel_size=3, padding=1).cuda().train()
x = torch.randn(2, 4, 128, 160, 112, device="cuda")
compiled = torch.compile(model, backend="inductor", fullgraph=True)

y = compiled(x)                 # 前向：成功
torch.cuda.synchronize()
y.mean().backward()             # 反向：失败，进程 SIGSEGV / 139
torch.cuda.synchronize()
PROBE A

Pointwise

x + 1 经 compile 执行成功，Triton 基础路径正常。

PROBE B

小 3D 图

Conv3d → InstanceNorm3d → LeakyReLU，32³ 前向+反向成功。

PROBE C

真实 patch 前向

batch 2、128×160×112 的 Conv3d 前向成功。

PROBE D

真实 patch 反向

同一 Conv3d 加入 backward()，稳定触发 addSource 与 SIGSEGV。

04 / 关键证据

失败 IR 来自 Conv3d backward 的 4-warp 共享内存变体

失败 kernel：triton_per_fused_convolution_backward_1.llir实际缓存产物
@global_smem = external local_unnamed_addr addrspace(3)
  global [0 x i8], align 16

%57 = getelementptr inbounds nuw i8,
      ptr addrspace(3) @global_smem, i64 %56, !dbg !21
失败变体
BJN… / triton_per_fused_convolution_backward_1，num_warps=4；有 global_smem，仅生成至 .llir/.ttgir/.source，未生成 .amdgcn/.hsaco。
成功变体
MY5… / triton_per_fused_convolution_backward_1，num_warps=1；无该 shared-memory IR，成功生成有效 AMD GPU HSACO ELF。
外部编译器对照
把失败的真实 .llir 直接交给命令行 dcc 与 clang，两者均解析成功（exit 0）。
Inductor 源节点
生成 Python 明确将该 kernel 标记为 Original ATen: aten.convolution_backward；其 max_autotune=False，不是用户开启最大 autotune 所致。
05 / 影响与恢复

训练无法安全使用 compile；失败后还会遗留 data-loader 子进程

训练影响

使用默认 nnU-Net 3D plans 的训练在首个大体积 Conv3d backward 触发后退出。父进程出现 SIGSEGV（exit 139）；观察到 data-loader 子进程可能不随父进程退出，虽不占 GPU，但会继续消耗 CPU / RAM。

当前稳定回退

设置 nnUNet_compile=f。这只禁用 JIT 包装；不会改变模型、默认 plans、batch、优化器、epoch、数据增强或 fold 定义。

请勿用 PyPI generic Triton 覆盖当前包，也不要以来源不明的 wheel 降级。任何尝试版本应同时满足 dtk2604 和 torch290 ABI 标识，并重新执行本报告的最小 Conv3d backward 探针。
