## 3. 决策与协议(负责人 2026-09-01 拍板)

选 B(重训)。按 ADR-0003 §8,原 ADR-0002/0003 自重训起失效,须重走训练→校准→冻结并出新 ADR。**本次重训协议(负责人明示的 deltas)**:

| 维度 | 原协议(ADR-0002/0003) | 新协议(v2) |
|---|---|---|
| SSA plans | 派生 `nnUNetPlans_SSA_bs16_v1`(batch-only delta 特例) | **标准 `nnUNetPlans`,与其余四挑战同法** |
| 并行 | 单卡(每挑战);SSA 特例 8 卡 | **全部 4×DCU DDP**(`-num_gpus 4`,实例现役 4 卡) |
| 精度 | autocast 默认(fp16) | **BF16**(`torch.set_autocast_dtype('cuda', bfloat16)`,torch 2.9 API) |
| trainer | `nnUNetTrainer250Epochs`(原装文件随重置消失) | **现有 `nnUNetTrainer_250epochs`**(重构后 nnunetv2 内建)+ 包外 BF16 子类,**经 fork 自带 `nnUNet_extTrainer` 扩展点接入,零 nnunetv2 改动**(负责人明示不补装包内文件) |
| 轮数/迭代 | 250 epochs × 250 iter(62,500 步) | 不变(`nnUNetTrainer_250epochs` 语义) |
| 全局 batch | GLI/MEN/METS/PED=2;SSA=16 | 统一 8(= plans 本地 2 × 4 卡) |
| 数据/plans/fold | ADR-0003 §2 冻结 | 同一批文件(hash 对账见 §2) |

训练命令(每挑战一条,顺序 SSA→PED→METS→MEN→GLI,小挑战先行作 shakedown):

```
nnUNetv2_train Dataset<id> 3d_fullres 0 -tr nnUNetTrainer_250epochs_bf16 -p nnUNetPlans -num_gpus 4
```

- BF16 trainer 子类:`l2-instrument-v2/trainer/nnunet_trainer_v2_bf16.py`(job 自有物,存受控树;`nnUNet_extTrainer` 指向其目录),内容 = 继承现有 `nnUNetTrainer_250epochs`,`__init__` 内 `torch.set_autocast_dtype('cuda', torch.bfloat16)`。
- 配方:`deploy/jobs/retrain_instrument_v2.sh`(幂等:completion 审计存在即跳过;checkpoint_latest 存在即 `--c` 续训)。
- 产物根:`/root/private_data/ctmr/instruments/l2-instrument-v2/`(results/ audit/ logs/ trainer/);训练完成并核验后再择机替换 `instruments/nnunet_results` 悬空农场(旧农场先归档改名,不删除)。

## 4. 环境事实(2026-09-01 现场)

- 实例现役 **4 张 DCU**(`torch.cuda.device_count()==4`;原 8 卡契约不再成立);DTK 26.04、torch 2.9.0+das.opt1、MONAI 1.6.0、nnunetv2 2.8.1(DTK 构建裁剪版,`-num_gpus` DDP 与 `nnUNet_extTrainer` 为其自带能力)
- fork 的 trainer 解析:包内查不到即按 `nnUNet_extTrainer`(os.pathsep 分隔多目录)逐目录扫描类名——已端到端验证(类正确解析、bf16 API 生效)
- 基类 autocast 为 `autocast(self.device.type, enabled=True)`:dtype 由 torch 全局 autocast dtype 决定,默认 fp16;`set_autocast_dtype` 在每个 DDP worker 的 trainer `__init__` 中执行(spawn 进程各自生效)
