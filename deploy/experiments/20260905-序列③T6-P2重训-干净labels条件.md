## 4. 执行中发现并修复的缺陷(全部 TDD 钉板,训练零中断)

本票是 mask `dev-eval watch` 离线链(#279 改造后)的**首个端到端消费者**,先后撞出三个缺陷,均在运行中修复(watch 幂等自愈,已评点补评,训练进程零触碰):

1. **装配形参错位**(生产首撞):watch `main()` 以 `partial(generate_cohort, cohort=…, spacings=…, masks=…)` 装配 sampler_factory,`WatchEngine` 的合同是 positional `(checkpoint_path, out_dir)`——第二位置参落在 `cohort` 形参,`TypeError: got multiple values` 每 eval 点被 skip。修复:lambda 各参落其名;新装配合同测试驱动 `main()` 断言逐参落位。
2. **L2 面仪器 v2 树失配**:仪器 results 树序列②已换 v2 布局(`nnUNetTrainer_250epochs_bf16__nnUNetPlans_v2bs8__3d_fullres_bs8`),冻结 `INSTRUMENT_SPECS` 锚与之失配 → `dataset.json` FileNotFoundError,run_fail 16/16。修复:`L2TrendRunner` 加 opt-in `autodiscover_specs`——按树实况解析每挑战 `<trainer>__<plans>__<config>`(恰一目录三段式,不猜,响亮死),`dataclasses.replace` 构造 per-runner 覆写,**冻结锚零改动**(重钉待 v2 校准同批,#310;etwt 脚本同族机制);watch 加 `--instrument-specs-autodiscover` 旗标;等价门参照面登记第三次 declared evolution(#280/#279 先例)。
3. **包外 trainer 变量缺失**:v2 trainer 是包外类,缺 `nnUNet_extTrainer` 环境变量即响亮死(etwt §193 同款接入)。修复:watch_loop heredoc export(默认 `l2-instrument-v2/trainer`)。

修复后 e20 起四面全通(FID + L2 trend + round-trip Dice,#314 RAS 修复的 RoundTripDice 首个端到端消费者)。代码面 4 枚提交(47c6709 / 4bf36f0 / a4d46d1 / 78eaea7),mask+modality_label 家族 168 passed,全量套件 1102+15 passed / 12 skipped(服务器 full-dependency tier;6 个初现失败为部署树缺 pyproject/deploy 文件,补齐后全绿)。
