## 4. RadImageNet 权重对证

- `RadImageNet-ResNet50_notop.pth`（Warvito hub loader 期望文件）Drive 原件被平台代理拦截
  （gdown 报 drive 配额/权限）；负责人提供 Kaggle 镜像 `dbpdenesh/radimagenet-resnet50-notop`
  tarball，**与负责人浏览器下载的 Drive 原件 md5 逐位一致**（`5d9c98abc33075626dd7629acd68af40`，
  94465691 B）——Kaggle 镜像即原版，371 plain keys 与 Warvito `ResNet50()` strict-load 全匹配。
- 已装入 torch.hub 缓存（`/root/.cache/torch/hub/checkpoints/`），hub loader 直接命中；
  持久盘留档 `/root/private_data/ctmr/models/radimagenet_candidates/`。
- **锚点复现结果（如实登记）**：以该权重对基底 epoch_20 样本重算 FID 与基线记录
  （selection.json，m=3.3979697571412877）**不复现**——worst |Δ|=1.06（t1n/yz 平面），
  m 偏 3.7e-2（约 1%），且 yz/zx 平面偏移大、xy 最小。权重逐位相同、样本与 real bank 缓存
  相同，唯一变量为服务器重组后的**预处理栈版本**（MONAI/nibabel 插值实现）——旧栈环境随
  易失盘消失，逐位复现物理不可能。含义：新旧栈 FID 读数不可直接混比。
- **处置（判定线零改动）**：同仪器重算——以当前栈（现权重+现包版本）重提 real bank
  （`$P1_ROOT/dev_eval/reference_reinstr/`，不覆盖基线缓存）并重算基底全部 7 个 eval 点的
  generated FID（`reinstrument_base_trend.json`，schema `p1-dev-fid-reinstrument/1`）；
  T7 侧车 bank 源改指向同仪器重提产物（launcher `REF_BANK_SRC`），T7 与基底 trend 全程
  同栈同 bank 可比。基线历史记录（3.3980 等）保留为历史事实。

## 5. DCU torch 栈被 PyPI 覆盖事故（如实登记）

- 症状：torch.cuda 枚举 0 卡（`Found no NVIDIA driver`），而 hy-smi/rocminfo/hipGetDeviceCount
  （ctypes 直调 libamdhip64）全部正常（4×gfx936）。
- 根因：系统 python 的 torch 被换成 **PyPI CUDA 版 2.13.0+cu130**（torchvision 0.28.0 配套，
  site-packages mtime 2026-09-01 16:26；`torch.version.hip=None`）。DCU 版
  `2.9.0+das.opt1.dtk2604` 被顶掉。16:26 时段本会话仅运行纯 python 脚本（无 pip 调用），
  覆盖来源非本会话命令（嫌疑：jupyter 内人工操作或平台自动化，未定论）。
- 修复（防复发要点：**永远 `--no-deps` + sourcefind 直链**）：卸 PyPI torch/torchvision →
  sourcefind DAS1.8 直链装回 `torch-2.9.0+das.opt1.dtk2604`、
  `torchvision-0.24.0+das.opt1.dtk2604.torch290` → numpy 2.2.6 降回 **1.26.4**（DCU torch
  按 1.x 编）。验证：cuda True / 4 卡 / flash_attn+monai import ok。
- 本地（mac）开发环境同步重建：uv venv + requirements.txt + pytest，全量测试
  **953 passed, 6 skipped**。
